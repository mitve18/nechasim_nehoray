# מנסח ההסכמים

אפליקציית ווב פנימית שמנסחת הסכמים בעברית בעזרת OpenAI (gpt-4o, ו-gpt-4.1-mini לשלבים הזולים), על בסיס מאגר הסכמים קיים ב-Google Drive.

> הפרויקט נבנה בשלבים. האתר רץ ב-Render, והסנכרון היומי רץ ב-GitHub Actions.

## מה האתר עושה
| דף | מה עושים בו |
|---|---|
| **שאלו על המסמכים** (דף הבית) | שאלה בשפה חופשית על המאגר. התשובה מפנה למסמך, לסעיף ולעמוד |
| **הסכם חדש** | טופס או שיחה ← טיוטה שנכתבת על בסיס הסכמים קיימים, עם בדיקת דרישות חוק ובדיקה משפטית מעמיקה (אופציונליות) |
| **טיוטות** | כל טיוטה נשמרת אוטומטית, נערכת בעורך ומיוצאת ל-Word |
| **חוזים** | כל המסמכים במאגר עם הנתונים המובנים שלהם (צדדים, תאריכים, סכומים, גוש/חלקה). העלאת קבצים, וצילום מסמך ישירות ממצלמת הטלפון |
| **סטטוס** | מצב הסנכרון והעיבוד של כל קובץ, עם ייצוא ל-Word ול-Excel |
| **ניהול** (admin) | משתמשים, עלויות OpenAI לפי משתמש ותקופה, לוג הסנכרון |

## איך הפרויקט משתמש ב-Agno
מנוע הניסוח ([`app/draft.py`](app/draft.py)) בנוי משלושה Agents של [Agno](https://docs.agno.com) (גרסה מוצמדת ב-`requirements.txt`).
לכל Agent יש תפקיד אחד, והוא רץ במודל הזול ביותר שמספיק לתפקיד:

| Agent | מודל | מה הוא רואה | מה הוא מחזיר |
|---|---|---|---|
| **Intake** | `gpt-4.1-mini` | השיחה, ותוצאות החיפוש **כתקצירים בלבד** | שאלות השלמה, או "מוכן" ועד 2 מסמכים לדוגמה (`Intake`) |
| **Writer** | `gpt-4o` | השיחה, ו**הטקסט המלא** רק של מסמכי הבסיס והדוגמאות שנבחרו | ההסכם כטקסט רגיל (שורה ראשונה: כותרת), **בהזרמה** לממשק |
| **Reviewer** | `gpt-5.5` | הבקשה והטיוטה (רק ב"בדיקה משפטית מעמיקה") | תיקונים נקודתיים והערות (`Review`), לא את כל ההסכם מחדש |

- **למה ככה:** בעבר כל סבב, גם סבב של שאלות השלמה, שילם על כ-50 אלף טוקנים של דוגמאות ב-gpt-4o. עכשיו סבב שאלות
  נעצר ב-Intake הזול, והטקסט המלא נשלח פעם אחת, רק ל-Writer. הבודק מחזיר תיקונים (`find`/`replace`) והקוד מחיל אותם
  (`apply_edits`); הפלט של gpt-5.5 הוא החלק היקר, וכך הוא קטן בערך פי 10. תיקון שהקטע שלו לא נמצא בטיוטה מדולג ומדווח בהערות.
- **הזרמה:** `/api/draft` מחזיר NDJSON (שורת JSON לכל אירוע: `delta`, `reviewing`, `result`, `error`), וההסכם
  מופיע בחלונית תוך כדי כתיבה. ה-Writer כותב טקסט ולא JSON, כי JSON חלקי אי אפשר להציג. הסכם שהגיע לתקרת הטוקנים
  ונקטע מוחזר כשגיאה ברורה, ולא כהסכם חסר.
- **תיקון בצ'אט** להסכם שכבר נוסח (`revise`): ישר ל-Writer, בלי Intake, חיפוש ודוגמאות. ההסכם עצמו כבר בשיחה,
  והממשק משאיר את רשימת המקורות של הניסוח המקורי.
- **החיבור בין ה-Agents** הוא קוד Python רגיל ולא `Team` של Agno: הסדר קבוע, ומודל "מנהל" היה מוסיף קריאה ועלות בכל סבב.
- **Tool:** `search_agreements` (של ה-Intake) מחפש ב-pgvector ב-Neon (`store.search`). ה-Agent מחליט על שאילתת החיפוש בעצמו.
  בחרנו tool ולא Knowledge של Agno, כי הטבלה הקיימת שומרת גם תקציר, טקסט מלא וקישור ל-Drive, והסנכרון משתמש בכולם.
  ה-Intake יכול לבחור רק מסמכים שהחיפוש החזיר; `file_id` מומצא לא נכנס.
- **שאלות על המסמכים** ([`app/ask.py`](app/ask.py)): Agent אחד (`gpt-4o`) עם כלים, ובשאלה על הרבה מסמכים הוא מפעיל
  map-reduce דרך `ask_documents`: קורא זול (`gpt-4.1-mini`) רץ במקביל על כל מסמך ומחזיר רק את הקטעים הרלוונטיים.
- גם התקצירים בסנכרון נוצרים ב-Agent של Agno (`gpt-4o`, פעם אחת לכל מסמך). ה-OCR הוא Tesseract, עם OCR של Google Drive לעמודים קשים.

## דרישות מקדימות
- Python 3.11 ומעלה

## הגדרת פרויקט Google Cloud

### 1. יצירת פרויקט והפעלת ה-API
1. היכנס ל-[Google Cloud Console](https://console.cloud.google.com/) וצור פרויקט חדש (למשל `agreements-drafter`).
2. בתפריט: **APIs & Services → Library**, חפש **Google Drive API** ולחץ **Enable**.

### 2. מסך ההסכמה (OAuth consent screen)
1. **APIs & Services → OAuth consent screen** (נקרא גם **Google Auth Platform**).
2. סוג משתמש: **External** (או **Internal** אם יש לכם Google Workspace).
3. מלא שם אפליקציה ומייל תמיכה.
4. ב-**Data Access / Scopes** הוסף את ההרשאה `https://www.googleapis.com/auth/drive` (קריאה וכתיבה מלאה).
5. **חשוב:** ב-**Audience** לחץ **Publish app** כדי להעביר את האפליקציה לסטטוס **In production**.
   באפליקציה בסטטוס *Testing*, ה-refresh token **פג אחרי 7 ימים** והסנכרון יפסיק לעבוד.
   אין צורך לעבור אימות (verification) של Google לשימוש פנימי. בזמן ההתחברות תופיע אזהרת "Google hasn't verified this app". לחץ **Advanced → Go to ... (unsafe)**.

### 3. יצירת פרטי OAuth
1. **APIs & Services → Credentials → Create Credentials → OAuth client ID**.
2. סוג אפליקציה: **Desktop app**.
3. הורד את קובץ ה-JSON ושמור אותו בתיקיית הפרויקט בשם `client_secret.json`. הקובץ כבר מוחרג ב-`.gitignore`, אל תעלה אותו ל-git.

### 4. צמצום הרשאות (מומלץ)
ל-Google אין הרשאה שמגבילה גישה לתיקייה אחת בלבד, ולכן `drive` מאפשר קריאה, כתיבה ומחיקה של **כל** ה-Drive של החשבון המחובר.
מומלץ ליצור חשבון Google ייעודי (למשל `agreements-bot@...`), לשתף איתו **רק** את תיקיית ההסכמים (הרשאת עריכה), ולהתחבר בשלב הבא עם החשבון הזה.

> אם ה-refresh token הופק עם scope אחר (למשל `drive.readonly`), הסנכרון ייכשל עם `invalid_scope`. צריך להפיק token חדש.

## איפה שמים סודות
הסודות בפרויקט הם `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`, `OPENAI_API_KEY`, `DATABASE_URL`, `SECRET_KEY`, `ADMIN_PASSWORD` ו-`GH_DISPATCH_TOKEN`. הרשימה המלאה של המשתנים, עם הסבר מאיפה משיגים כל אחד, נמצאת ב-[`.env.example`](.env.example).

### פיתוח מקומי
- הסודות נשמרים **רק** בקובץ `dev\.env`. הקובץ מוחרג ב-`.gitignore`.
- תיקיית הפרויקט מסונכרנת ב-**Qsync**, ולכן `.env` מועתק גם לשרת הסנכרון ולכל מחשב מסונכרן.
  מומלץ להחריג אותו מהסנכרון: ב-Qsync ← **Preferences ← Filter Settings**, הוסף את שם הקובץ `.env` לרשימת הקבצים המסוננים.

### פרודקשן (Render)
- נכנסים ל-Render ← השירות `agreements-drafter` ← **Environment**.
- מזינים שם ידנית כל משתנה שמוגדר ב-[`render.yaml`](render.yaml) עם `sync: false`.
- Render לא קורא את קובץ `.env`, והערכים לעולם לא נכנסים לקוד.

### אסור
- להעלות סודות ל-git, כולל בקבצים שנמחקו אחר כך, כי הם נשארים בהיסטוריה.
- להדביק סודות בצ'אט, במייל או בהודעות.
- לשמור סודות בקבצי טקסט פזורים, כמו `client.txt` או `token.txt`.

### אם סוד דלף
מבטלים אותו מיד ומנפיקים חדש:

| סוד | איך מבטלים ומנפיקים מחדש |
|---|---|
| `GOOGLE_CLIENT_SECRET` | Google Cloud Console ← Credentials ← ה-OAuth client ← **Reset secret**. אחר כך מפיקים refresh token חדש |
| `GOOGLE_REFRESH_TOKEN` | [myaccount.google.com/permissions](https://myaccount.google.com/permissions) ← האפליקציה ← **Remove access**. אחר כך מריצים שוב `scripts/get_refresh_token.py` |
| `OPENAI_API_KEY` | [platform.openai.com/api-keys](https://platform.openai.com/api-keys) ← Revoke למפתח ויצירת מפתח חדש |
| `DATABASE_URL` | Neon ← הפרויקט ← Roles ← Reset password, ואז מעתיקים את ה-connection string החדש |
| `SECRET_KEY` | מפיקים מפתח חדש (`python -c "import secrets; print(secrets.token_urlsafe(48))"`) ומעדכנים ב-Render. כל המחוברים מתנתקים |
| סיסמה של משתמש | admin נותן סיסמה חדשה בדף `/admin/users`. המשתמש מתנתק מיד מכל הדפדפנים |
| `GH_DISPATCH_TOKEN` | GitHub ← Settings ← Developer settings ← Fine-grained tokens ← Revoke, ויוצרים token חדש |

אחרי ההנפקה מחדש מעדכנים את הערך החדש ב-`.env` וב-Render ← Environment.

<div dir="rtl">

- לוג ריצות הסנכרון: `/admin/sync`.
- הסנכרון היומי רץ ב-GitHub Actions ([`.github/workflows/sync.yml`](.github/workflows/sync.yml)), והרצה ידנית: Actions ← sync ← **Run workflow**.
- **רק מסמכים חדשים או ששונו עוברים עיבוד** (חילוץ, OCR, תקציר ו-embedding). מסמך שכבר במאגר לא עובר OCR או מודל שוב.
  שינוי שם בלבד: `modifiedTime` משתנה אבל ה-md5 של התוכן מ-Drive זהה, ולכן רק השם מתעדכן (`store.touch`), בלי עלות.
  (ל-Google Docs אין md5 ב-Drive, ולכן הם עוברים עיבוד בכל שינוי, כמו קודם.)
- **OCR בשתי שכבות** ([`app/extract.py`](app/extract.py)), בלי מודל שפה ובלי עלות:
  1. **Tesseract** (עברית + אנגלית) על כל עמוד סרוק. ב-PDF ההחלטה היא **לכל עמוד**: נספח או עמוד חתימות סרוקים בתוך
     PDF דיגיטלי עוברים OCR, ושאר העמודים נקראים ישירות. לפני ה-OCR כל עמוד עובר: גווני אפור וניגודיות מלאה,
     הגדלה פי 2 לתמונה צרה מ-1600px, וסיבוב לפי זיהוי הכיוון של Tesseract (OSD), לעמוד שנסרק הפוך או על הצד.
     ב-Actions מותקנים המודלים המדויקים של [`tessdata_best`](https://github.com/tesseract-ocr/tessdata_best) לעברית ולאנגלית.
  2. **OCR של Google Drive** לעמוד שקיבל ב-Tesseract ציון מתחת ל-`FALLBACK_BELOW` (75): העמוד מועלה כתמונה ומומר
     ל-Google Docs עם זיהוי טקסט בעברית, הטקסט מיוצא והעותק נמחק (`drive.ocr_image`). חינם, ובעברית בדרך כלל מדויק
     יותר מ-Tesseract. רק בסנכרון של קובץ חדש או ששונה. אם Drive נכשל, נשאר הטקסט של Tesseract והסנכרון ממשיך.
     הסף משוער: כדאי לכייל אותו לפי הציונים במאגר.
- Tesseract ב-Windows: מתקינים את ה-installer של [UB Mannheim](https://github.com/UB-Mannheim/tesseract/wiki), ובמסך הרכיבים מסמנים
  **Additional language data → Hebrew**. הקוד מחפש את `tesseract` ב-PATH, ואחר כך ב-`C:\Program Files\Tesseract-OCR\tesseract.exe`.
  נתיב אחר: מגדירים `TESSERACT_CMD`. בדיקה: `python -m app.extract --ocr scan.pdf`. אופציונלי, כדי לקבל תוצאות כמו ב-Actions:
  מורידים את `heb.traineddata` ו-`eng.traineddata` מ-`tessdata_best` לתיקייה `tessdata` של ההתקנה (דורסים את הקיימים).
- קובץ שנכשל בחילוץ או ב-OCR לא נכנס למאגר, ולכן ינוסה שוב בריצת הסנכרון הבאה.
- תמונות (png, jpg, tif, webp, ותמונות HEIC מאייפון) עוברות OCR כמו PDF סרוק, כולל TIFF עם כמה עמודים.
  צילום טלפון מסובב קודם לפי תג הסיבוב שלו (EXIF), ואחר כך לפי זיהוי הכיוון. לפני ה-OCR של Drive (שמקבל רק עד 2MB)
  התמונה מוקטנת לצלע ארוכה של עד 3000px (`OCR_MAX_SIDE` ב-[`app/drive.py`](app/drive.py)), כי צילום של 12–48 מגה-פיקסל גדול מזה.
- Word: DOCX נקרא ישירות; DOCX עם עמודים סרוקים כתמונות וכמעט בלי טקסט עובר OCR על התמונות.
  DOC ישן (Word 97-2003) מומר לטקסט דרך Google Drive: עותק זמני ב-Google Docs, ייצוא טקסט ומחיקת העותק.
- לכל מסמך שעבר OCR נשמר ציון איכות (0–100): ממוצע הביטחון של Tesseract במילים שזיהה. מוצג בחלון הפרטים של הקובץ.
  הציון הוא תמיד של Tesseract, גם כשעמוד נקרא מחדש ב-Drive: הוא מראה כמה הסריקה קשה, ומסמך עם ציון נמוך עדיין
  כדאי לבדוק מול הקובץ המקורי.

### פאנל הקבצים ונתונים מובנים
- **טבלת `files`:** הסנכרון רושם כל קובץ שהוא רואה ב-Drive עם סטטוס: `indexed` (מאונדקס), `failed` (נכשל, עם הסיבה),
  `unsupported` (סוג לא נתמך) או `queued` (בתור: הועלה מהאתר או סומן "נסה שוב"). "לא נתמך" לא מכשיל את ה-workflow.
- **נתונים מובנים:** אותה קריאה למודל שכותבת את התקציר מחזירה גם סוג מסמך, צדדים, מספר תוכנית, מיקום, גוש/חלקה,
  תאריכים, סכומים ועמודים (עמודה `metadata` מסוג jsonb, ו-`end_date` בעמודה נפרדת). שדה שלא כתוב במסמך נשאר null.
- **Backfill:** בכל סנכרון, מסמכים בלי נתונים מובנים (או עם `metadata_version` ישן) מושלמים מהטקסט ששמור במסד,
  בלי הורדה מ-Drive ובלי OCR. מוסיפים שדה? מעלים את `METADATA_VERSION` ב-[`app/store.py`](app/store.py), והסנכרון הבא משלים.
- **משתמשים אישיים** ([`app/auth.py`](app/auth.py)): כל עובד נרשם באימייל ובסיסמה (bcrypt) ב-`/register`, והאתר זוכר
  אותו ל-30 יום (עוגייה חתומה ב-`SECRET_KEY`, HttpOnly, SameSite=Lax). כתובת מדומיין ב-`SIGNUP_DOMAINS` נפתחת מיד;
  כל כתובת אחרת ממתינה לאישור. פתוחים בלי כניסה רק `/login`, `/register`, `/healthz` והלוגו. בלי `SECRET_KEY`
  האתר חסום. בכל בקשה השרת בודק במסד שהמשתמש פעיל, כך שהשבתה או סיסמה חדשה מנתקות מיד.
  הגנות: עד 10 ניסיונות כניסה שגויים ב-15 דקות לכל IP ולכל כתובת, עד 5 הרשמות לכל IP, ובקשה שמשנה משהו ונשלחה
  מאתר אחר (Origin זר) נחסמת (CSRF).
- **מה של מי:** טיוטות ושיחות "שאלו" שייכות למשתמש, וכל שאילתה עליהן מסננת לפי `user_id` (משאב של משתמש אחר מחזיר 404).
  ארכיון ההסכמים, הסנכרון וההעלאה משותפים לכולם. עלויות, לוג הסנכרון וניהול משתמשים (`/admin/users`: אישור, השבתה,
  תפקיד וסיסמה חדשה למי ששכח) רק ל-admin. ה-admin הראשון נוצר מ-`ADMIN_EMAIL` ו-`ADMIN_PASSWORD`, ומקבל את הטיוטות
  שנוצרו לפני המשתמשים.
- **Agno:** `user_id` ומזהה השיחה (`session_id`) עוברים לכל `agent.run` לתיוג בלבד. ל-Agents אין `db`: ההיסטוריה
  נשמרת בטבלאות שלנו (`drafts`, `chats`), בלי pool שני ל-Neon ובלי כפילות.
- **העלאה מהאתר** (דף החוזים, למשתמשים עם הרשאת כתיבה): גרירה או בחירת קבצים, ובטלפון גם **"צלם מסמך"**, שפותח את
  המצלמה האחורית. צילום מקבל שם עם תאריך ושעה (`צילום 2026-10-28 14-30-05.jpg`), כי אייפון קורא לכל צילום `image.jpg`.
  הקובץ נבדק בשרת לפי סיומת, גודל (עד 20MB) ותוכן, ומועלה לתיקייה הראשית. שם קיים מקבל סיומת (1), (2).
  אחרי ההעלאה השרת קורא את הקובץ מ-Drive ומוודא גודל ו-md5 זהים, ורק אז הקובץ נכנס לתור העיבוד.
- **כפתור הסנכרון** מפעיל את ה-workflow דרך GitHub API (`GH_DISPATCH_TOKEN`, `GH_REPO`), לכל היותר פעם ב-5 דקות.

### שאלות על המסמכים וטופס הסכם חדש
- **שאלו על המסמכים** (דף הבית, [`app/ask.py`](app/ask.py)): Agent שעונה רק מהמאגר, עם ארבעה כלים: חיפוש סמנטי,
  רשימת כל המסמכים עם הנתונים המובנים (לשאלות על כל המאגר), קריאת מסמך מלא, ו-`ask_documents`.
- **חיפוש בסעיפים (היברידי):** כל מסמך נחתך לקטעים (`extract.chunk`): גבול בתחילת כל סעיף ראשי, עד כ-2,000 תווים
  לקטע, עם חפיפה של פסקה כשסעיף ארוך מתפצל. לכל קטע נשמרים הסעיף, העמוד שבו הוא מתחיל, embedding ו-`tsvector`
  (טבלת `chunks`). `search_documents` מחפש גם לפי משמעות וגם לפי מילים מדויקות (מספר גוש, מספר תוכנית, שם צד),
  ומאחד את שתי הרשימות ב-RRF בשאילתת SQL אחת (`store.search_chunks`). הוא מחזיר 8 קטעים, ולא מסמכים מלאים.
  מסמכים קיימים נחתכים בסנכרון מהטקסט השמור, בלי Drive ובלי OCR (רק embeddings, כ-40 סנט ל-1,000 חוזים).
  משנים את החיתוך? מעלים את `CHUNK_VERSION` ב-[`app/store.py`](app/store.py). ה-Intake של הניסוח ממשיך לחפש לפי
  תקציר (`store.search`), כי שם מחפשים "הסכם דומה" ולא סעיף.
  כל טענה מפנה למסמך, לסעיף ולעמוד. ציטוט של מסמך שהכלים לא החזירו נמחק לפני שהוא מגיע לממשק.
- **`ask_documents` (map-reduce):** לשאלה על הרבה מסמכים ("באילו הסכמים יש סעיף שיפוי, ומה הסכום?"). עד 20 מסמכים
  בקריאה אחת, 5 במקביל. לכל מסמך, קורא ב-`gpt-4.1-mini` מקבל את השאלה ואת הטקסט המלא, ומחזיר רק ציטוטים עם סעיף ועמוד,
  או "לא רלוונטי". ה-Agent הראשי מקבל רק את הקטעים, ולכן מכסה הרבה יותר מסמכים מאשר בקריאת כל מסמך במלואו,
  ובפחות טוקנים של gpt-4o. מסמך שהקריאה שלו נכשלה מסומן כך, והתשובה ממשיכה בלעדיו.
- **סימוני עמודים:** הטקסט השמור של PDF ותמונות מתחיל כל עמוד ב-`[עמוד N]`, וממנו התשובות לוקחות מספר עמוד.
  מסמכים מלפני השינוי מקבלים את הסימונים בסנכרון הבא (הורדה וחילוץ מחדש, בלי מודל; במסמך סרוק זה OCR מלא).
  Word אין לו עמודים קבועים, ולכן בו התשובות מציינות סעיף בלבד. לפני הניסוח הסימונים מוסרים מהדוגמאות.
- **הסכם חדש:** טופס (סוג, מהות, חוזי בסיס, צדדים, תנאים, נטיית ניסוח) שהופך להודעה אחת למודל, בלי שאלות השלמה.
  "בדיקת דרישות חוק" מוסיפה ל-Writer את כלי `web_search` של OpenAI; "בדיקה משפטית מעמיקה" מעבירה את הטיוטה ל-Reviewer
  (`REVIEW_MODEL` ב-[`app/draft.py`](app/draft.py)), שמחזיר תיקונים נקודתיים והערות. אם הבדיקה נכשלת, הטיוטה חוזרת בלעדיה.
  תיקונים בצ'אט נשלחים בלי שתי האפשרויות.

### טיוטות, עורך ועלויות
- **טיוטות** (טבלת `drafts`): כל ניסוח נשמר מיד, וכל עריכה נשמרת אוטומטית אחרי שנייה וחצי, עם העיצוב
  והשיחה. פתיחה של טיוטה מחזירה אותה לעריכה ואת השיחה להמשך. טיוטות נשמרות ללא הגבלת זמן ונמחקות רק ידנית.
  כל משתמש רואה רק את הטיוטות שלו.
- **שיחות "שאלו"** (טבלת `chats`): כל שיחה נשמרת אחרי התשובה הראשונה, עם הציטוטים, ומופיעה ב"השיחות שלי" בצד המסך.
  שאלת המשך בשיחה שמורה לוקחת את ההיסטוריה מהמסד (40 ההודעות האחרונות), ולא ממה שהדפדפן שלח.
- **משוב** ("מרוצים מנוסח ההסכם?" מתחת לשיחה, אופציונלי): נשמר בעמודה `drafts.rating` (1, 0, 1-). בניסוחים הבאים
  החיפוש במאגר (`store.search` עם `learn=True`) מעלה מעט מסמכים שטיוטות שנוסחו מהם קיבלו משוב טוב, ומוריד מסמכים
  שקיבלו משוב רע.
- **עלויות** (טבלת `api_usage`): כל קריאה ל-OpenAI נרשמת עם הטוקנים והעלות בדולרים: ניסוח וחיפוש באתר (`draft`),
  ותקציר ו-embedding בסנכרון (`sync`). העלות מחושבת לפי `PRICES` ב-[`app/store.py`](app/store.py); מחליפים מודל או
  שהמחיר משתנה? מעדכנים שם. העלות של טיוטה היא סכום כל הקריאות בשיחה שלה (מזהה `conversation`), כולל שאלות ותיקונים,
  ושל כל ה-Agents (Intake, Writer, Reviewer). כל שורה נרשמת עם המודל שלה, כך שאפשר לראות כמה עולה כל שלב.
- **העורך** מאפשר הדגשה, נטוי, קו תחתון, גודל גופן, יישור, כיוון כתב ורשימות. בייצוא ל-Word פסקה מעוצבת נשמרת
  כמו שהיא, ופסקה בלי עיצוב עוברת את זיהוי התבניות הרגיל (סעיפים, הואיל, חתימות).
